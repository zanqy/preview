Alur Kerja Tharra

Visualisasi end-to-end: dari siswa menulis surat (anonim) sampai aspirasi tercatat, bisa dilacak, dan (rencana) dibalas lewat jalur bernama.

alur utama di perangkat (lokal) jalur AKAR (segera hadir)
Langkah 1Mulai

Buka amplop & masuk ke kartu surat

Halaman intro menampilkan amplop “KATAKAN”. Siswa mengklik amplop → animasi terbuka → formulir (kartu surat) tampil. Gerakan hanya merespons aksi pengguna.

Intro (amplop tertutup)→Kartu terbuka (form)
Langkah 2Lokal (perangkat)

Tulis aspirasi (anonim)

  • Siswa menulis isi aspirasi (minimal 20 karakter, batas 600). Sepenuhnya anonim — tanpa nama, tanpa kelas.
  • Draf tersimpan otomatis di perangkat (localStorage) saat mengetik, jadi tidak hilang bila halaman ditutup sebelum kirim.
Langkah 3Kirim ke server

Kirim surat → API Tharra

  • Validasi sisi klien (isi cukup panjang). Jika lolos, formulir mengirim POST berisi aspirasi ke endpoint /api/aspirasi (server Tharra).
  • Jika gagal terhubung, pengguna diminta coba lagi (di host demo statis, pengiriman asli diarahkan ke situs Tharra).
Langkah 4Tercatat

Server terima → kode tiket & bukti

  • Respons sukses mengembalikan kode tiket (kode_tiket). Tampilan berubah ke status “TERCATAT” (stempel, kutipan, nomor).
  • Aspirasi juga dicatat di perangkat (riwayat lokal). Siswa bisa simpan kartu (PNG, berisi QR ke cek status), salin kode, atau tulis surat lain (draf dibersihkan).
  • Tujuan produk (sesuai salinan): surat dibaca pengurus OSIS dan dirangkum berkala.
Nomor tiketSimpan kartu (QR)Salin kode
Langkah 5Lacak

Cek status aspirasi

Dengan kode tiket (atau tautan/QR), siswa membuka halaman /cek-aspirasi untuk melihat status aspirasinya. Ini menutup loop: kirim → tercatat → bisa dipantau.

Jalur keduaAKAR · segera hadir

Jalur bernama (rencana)

  • Menyertakan identitas (NIS & nama) sebagai kunci pembicara.
  • Ruang bicara dengan humas OSIS (bisa menunggu balasan/berdiskusi, tidak berhenti di kotak masuk).
  • Nomor tiket untuk melacak percakapan. Saat ini ditandai “sedang dibangun”; jalur anonim utama tetap berjalan.

Catatan: Diagram ini merangkum alur yang terlihat di antarmuka Katakan (Tharra) — pengiriman anonim ke server, penerbitan kode tiket, penyimpanan lokal (draf/riwayat), dan pelacakan status. Detail proses internal OSIS di balik server tidak ditampilkan di UI.
